## trigger 設計：mixed
- 三個有標準「Use when」+ 具體語境：「Use when asked to monitor papers every day, mine buried research… separate promising work from hype」（paper-opportunity-radar）；orwell-writing 觸發動詞列舉完整（draft, rewrite, edit, review, polish, copyedit, simplify, humanize）。
- lead-research 的 description 是純能力陳述（「Provider-neutral deep-research orchestration…」），無觸發語；repo 內品質不一致。

## 寫作風格：good
- imperative、紀律性強、反幻覺條款密集且具體：「NOT FOUND beats inference」「Citation count is attention, not validity」「Never say monitoring is active until a recurring job actually exists」。
- 有角色分離的 why：「One agent cannot gather and verify the same claim. One agent cannot write and audit the same report」。
- 弱點：散文密度高、幾乎無 worked example（對比 ponytail/vercel 的 ❌/✅ 範式）；部分數字紀律（0–5 四維評分、2500 token 上限）未附校準依據。

## scope 清晰度：good
- 每個 skill 一個 job-to-be-done，但 job 本身很大（lead-research 是完整 multi-agent 研究 harness；repo-system-map 綁定單一固定交付物「isometric system map」且明禁降級：「a static image is not an acceptable fallback」）。單 job 但高複雜度、對 runtime 能力假設重（native delegation、canary agent），可移植性存疑。

## 其他觀察
