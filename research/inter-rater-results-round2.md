# Craft 判定一致性 — 第二輪(2026-08-18)

> 措辭紀律同第一輪:三位審查者是**同一個模型**在獨立 context 跑,這是
> **same-model, independent-context reliability**,不是 inter-rater reliability。

## 這一輪想回答什麼

第一輪(`inter-rater-results.md`)發現 L-004 最弱(κ=0.400),三位獨立指出同一個
邏輯矛盾,我據此改寫了 L-004(rubric 2.0.0)與 L-002(2.1.0)。
**但改完沒有再測** —— 這一輪就是把那個迴圈關起來。

同時修掉第一輪發現的定錨:發給審查者的 rubric 改用程式產生的**遮蔽版**。

## 主結果:迴圈**沒有關成**,而且原因比結果重要

同基準比對(兩輪都排除第一輪的 5 個定錨格,n 完全相同):

| 維度 | 條文有改? | 第一輪 κ / PA | 第二輪 κ / PA | Δκ |
|---|---|---|---|---|
| L-001 觸發設計 | ❌ **沒改** | 0.862 / 0.952 | 0.649 / 0.857 | **−0.213** |
| L-002 規則附 why | ✅ 改了 | 0.597 / 0.846 | 0.528 / 0.846 | −0.068 |
| L-003 scope 邊界 | ❌ **沒改** | 0.754 / 0.905 | 0.434 / 0.810 | **−0.319** |
| L-004 anti-hallucination | ✅ 改了 | 0.400 / 0.595 | 0.491 / 0.714 | +0.091 |
| **整體(n=55)** | | **0.628 / 0.824** | **0.539 / 0.806** | −0.089 |

### 結論 1:**兩個條文完全沒動的維度,變動幅度比我改過的還大**

L-003 在**零 rubric 改動**下 κ 掉了 0.319;L-001 掉了 0.213。
而我實際改寫的 L-002 只動了 −0.068,L-004 動了 +0.091。

> **在 n≈14 的規模,輪間變異吞掉了 rubric 修訂的效果。**
> κ 差 ±0.1~0.3 **無法歸因**於條文修改——這個「量測 → 修 → 再量測」的迴圈,
> 在這個樣本量下**不可判**。

這同時回頭削弱第一輪的分維度排名:L-004「最弱」(0.400)有多少是雜訊,現在說不清。

### 結論 2:**PA 比 κ 穩定得多,而 PA 保住了唯一重現的發現**

```
第一輪 PA:  L-001(.952) > L-003(.905) > L-002(.846) > L-004(.595)
第二輪 PA:  L-001(.857) > L-002(.846) > L-003(.810) > L-004(.714)
            ↑ L-004 兩輪都墊底

第一輪 κ:   L-001(.862) > L-003(.754) > L-002(.597) > L-004(.400)
第二輪 κ:   L-001(.649) > L-002(.528) > L-004(.491) > L-003(.434)
            ↑ 排序完全洗牌
```

**唯一跨輪重現的事實:L-004 的成對一致率在兩輪都是最低。**
κ 的排序不穩(第一輪最低是 L-004、第二輪是 L-003),PA 的排序保住了這一條。
這與 `agreement.py` 檔頭就寫的警告一致:κ 對邊際分布敏感,小樣本下極不穩定,
**兩個數字必須併看**。這一輪是那條警告的實證。

### 結論 3:整體數字是這批資料裡最可信的部分

整體 PA 0.824 → 0.806(幾乎不動),整體 κ 0.628 → 0.539。
**兩輪獨立執行、換了三位審查者實例,整體成對一致率只差 1.8pp。**
若要引用一個數字,引用這個,不要引用分維度的 κ。

## 那 rubric 的修訂還算數嗎?**算,但理由不是這次的數字**

L-004 與 L-002 的修訂是基於**質化證據**:三位審查者各自獨立指出
`pass_criteria` 與 `exemption` 兩條路徑對同一種 skill 同時成立、給出不同答案——
那是條文裡**可以直接讀出來的邏輯矛盾**,不需要 κ 來證明。

**但本輪不構成「修訂有效」的證據。** 兩個原因:
1. L-004 的改善(+0.091)落在無改動維度的變動範圍內(−0.319 ~ −0.213),無法區分於雜訊
2. 更根本的:審查者**被推向了修正的方向**(見下)

修訂保留,但**不宣稱它被量測驗證**。

## ⚠️ 本輪的四類污染,三類是我在「修正」時自己製造的

全部由審查者主動揭露,不在我的隔離清單裡。

### (1) 遮蔽版 rubric 洩漏上一輪的完整結果 —— 我造成的

我寫進 L-002/L-004 的「**為什麼要明訂**」理由段,原封不動留著:
`κ=0.597`、`κ=0.400`、`14 個分歧佔 8 個`、`n=55`、`查表型永遠塌在 mixed`、
甚至 `R1=mixed、R2/R3=good`。repo 名遮掉了,**修正的方向沒遮**。

S1 指出具體效果:

> 讀 kepano(查表型)之前,我已經被告知舊措辭讓查表型拿不到 good、而這是個已修的缺陷
> —— 那把我推向 good。我仍然讀了原文才判,但那個 prime 在。

**遮蔽器只遮 `evidence_refs`,沒遮理由段。**

### (2) 去識別化失敗:舉例的描述唯一指向特定 repo —— 我造成的

L-004 的 exemption 我寫了兩個「匿名」舉例,查證後**各自唯一指向樣本中的一個 repo**:

| 條文裡的舉例 | 唯一指向 | 已驗證 |
|---|---|---|
| 「某 skill 直述五條 ADHD 神經科學事實」 | `ayghri/i-have-adhd` | 該 repo 正文即 `Five facts drive every rule below` |
| 「記錄自家 index.html 的 CSS class」 | `shanraisshan/claude-code-best-practice` | 該 skill 正文即 `CSS classes and HTML patterns used in presentation/index.html` |

兩處都不透露 good/mixed/poor,但**都直接排除了該格的 `n/a`** ——
等於替審查者做掉了 `decision_order` 的第 2 步。S2 自陳:

> 沒有那一行,我很可能會把 i-have-adhd 讀成純互動風格方法論而判 n/a。
> 我的 `ayghri::L-004 = poor` 應視為被定錨,不是獨立判定。

**遮掉名字不夠——描述本身可以唯一識別。**

### (3) lint JSON 夾帶 L-001 的預判 —— 兩輪皆有,是常數

`craft_llm_todo` 每筆都有 `desc_has_trigger: true|false`,那正是 L-001 要判的事。
審查者在建立閱讀清單時就看到了。S1 說它有幾次不同意那個 flag
(regex 讀不出中文「當…時使用」、看不見 ayghri 的顯式 invocation/termination contract)。

**兩輪的 lint JSON 完全相同**,所以這是常數,不影響輪間比較,但**兩輪 L-001 的絕對值都被灌水**。

### (4) harness 自動注入 untrusted repo 的指令檔 —— 環境層,我無法控制

**三位審查者各自獨立把這件事列為問題**,S2 把它排第一:

> 讀 `research/inter-rater-repos/<dir>/` 底下的檔案,會讓 harness 把該 repo 自己的
> `CLAUDE.md`(與 `.claude/rules/*.md`)**當作專案指令**注入我的 context,未經請求。

兩個後果:

- **(a) 這是協定內部的一個活的 prompt-injection 面。**
  一個惡意 repo 可以放一份 `CLAUDE.md` 直接指示審查者怎麼評分。
  三位都把它當資料、都沒有遵循(符合 Iron Rule 7),
  但**這條路徑存在,而且是協定自己走進去的**。
- **(b) 這是不受控的審查者間變異。** 不同審查者依讀取順序觸發到不同的注入。
  S2 明說它「實質影響了我對 shanraisshan 的 L-003 判讀與對 caveman 的 L-002 判讀」;
  S3 說「若其他審查者沒觸發同樣的注入,這三個 repo 的可比性要打折」。

S1 另注意到 `obra` 與 `jnMetaCode` 的注入內容含強烈自我宣傳
(`94% PR rejection rate`、`extensively tested and tuned`),
`affaan-m` 的含一段對閱讀中 agent 說話的 `Prompt Defense Baseline`。

### 順帶:遮蔽只在「不重疊」的運氣下有效

S1 與 S2 都指出:遮蔽版仍保留大量**未遮的具名證據**(`Jeffallan(裸 MUST 堆疊=弱例)`、
`Leonxlnx/taste(全無 Use when=反例)`、S-001/S-002/S-003 的全部 evidence_refs…)。
它們**不在本批 15 個裡**,所以沒有污染本次判定——但如 S1 所言:
「**the mask only works by luck of non-overlap**」。

## 下一輪必須先修的四件(尚未執行)

1. **遮蔽器要一併移除理由段**(`為什麼要明訂` / `已知殘留限制` 等區塊),不只 `evidence_refs`
2. **舉例要去識別化到不可回推**,或整個移除;寫條文時就不該放唯一可識別的實例
3. **把抽樣到的 SKILL.md 複製到中性目錄**給審查者讀,或從 clone 內剝除
   `CLAUDE.md` / `AGENTS.md` / `.claude/rules/` —— 這同時堵住 prompt-injection 面
4. **從審查者版的 lint JSON 移除 `desc_has_trigger`**

**在這四件修好之前,不建議再跑第三輪** —— 會再燒一次預算換一批同樣不可判的數字。

## 最重要的一條教訓

第一輪的結論是「rubric 有歧義」。第二輪的結論是:

> **在 n≈15 的規模,這個量測方法本身無法解析 rubric 修訂的效果。**
> 兩個沒改條文的維度,變動比改過的還大。

要讓這個迴圈可判,需要的是**更大的樣本**(每維度 n≥40 才可能把 κ 的輪間變異壓到
能區分 0.1 級的效果),而不是更精緻的條文。這是本輪最有價值的產出——
它把「該不該繼續投資這條路」變成一個有數字的決定,而不是感覺。
