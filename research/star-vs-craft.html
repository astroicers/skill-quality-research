高星關聯的是 打包 ，
不是 工藝 。

分析各星數階層 Agent Skill repo 的特徵梯度後，證據指向一個反直覺的結論： skill 的星數關聯的是「可安裝／可發現／可信任」的打包面，不是內容工藝。 因此一個可靠的 skill 品質審查器，核心價值必然在 LLM 的質化判讀—— 自動化 lint 只能當 packaging 過濾器與安全門檻。

做了什麼

依星數分四層（T0–T3）分層抽樣 97 個 repo，標注三組混淆因子（作者聲量／發布世代／領域）， 以 F0 素人達 T2+ 的 14 個「純度樣本」作去混淆黃金對照組。 兩階段執行——deterministic script 先跑量化梯度，LLM 質化抽讀在後（54 份筆記、6 個平行 agent）； 三道 HITL gate 全程人工 binary 裁決，去混淆三道工序（素人復現／雙結果變數／因果機制） 過濾每一條差異化特徵。

四個關鍵發現

星數 ≠ 工藝packaging

5 條可量測的差異化特徵全是打包／行銷面（marketplace、一行安裝、tests、examples、before/after）； 寫作工藝（觸發設計／風格／scope）量化上全落 noise。觸發語存在性甚至在最低星層反而更高。

Fork 不背書packaging

所有差異化項對 fork_star_ratio 的相關幾乎全負—— 這些特徵跟按星同向、跟「fork 來實際使用」反向。差異化剖面未被使用行為背書。

低星高質有大量實證craft

400★ 的 turbo、968★ 的 jezweb、962★ 的 icm-architect，craft 都達 10k–100k 星級水準； 反之六位數星的樣本有關鍵字堆疊與重複。packaging 低 ≠ 品質差。

安全是本研究的差異化強項method

質化抽讀實證多個紅旗樣態（服從外部程式輸出＋抑制確認、hooks 常駐執行、憑證進 argv、自我更新） 與正面防禦樣態（把外部內容標 untrusted 的條款），落成 rubric 安全維度——一律門檻、不加分。

我們用自己的 rubric 審自己

packaging 0/14 → 11/14，hygiene 全過。補上了 marketplace.json、 一鍵 install.sh、examples、迴歸測試——都是這份研究自己指出的 gap。

  • 刻意留一個 gap 不補：rubric 認的「一行安裝」是 curl … | sh， 但一個做安全審查的工具去推廣 curl | bash 自相矛盾。 rubric 是 proposal 不是法律——它的價值在把取捨攤開，不是逼你把每格打勾。
  • 自審抓到工具自己的 bug：dir_examples 一度顯示「有」， 查證發現是被 research/repos/ 底下第三方 clone 的 examples/ 誤記——因此新增了 --exclude 參數。 這類 bug 不自審永遠不會發現。
  • 22 個自家 skill 回測，rubric 判錯 7 次：全部收斂到同一根因——樣態表是從「流程型」skill 歸納的，套到 canned-phrase / domain-lookup / dispatcher 型會字面誤判。7 條例外條款已補， 並由獨立 agent 用修訂後的 rubric 重審驗證誤判消除。

品質保證

pipeline 的統計／rubric 核心經獨立 code-review + 逐條覆核：無 crash-class bug； 7 條校準一致性問題全數處置（median 偶數 n 偏差、報告公式同步、marketing 權重上限、parser 對齊、 drift-guard selftest）。其中 2 條覆核時修正了 review 自身的因果判斷與嚴重性—— 不把審查當無誤的權威，也不把自己的產出說成零瑕疵。4 支 script 皆有 --selftest 護欄。

措辭紀律與限制

  • 只說「符合 X 星級剖面」，禁說「會得到 X 星」——星數還取決於發布時機、作者聲量、行銷，不在 artifact 可測範圍。
  • n = 54，不跑迴歸、不宣稱顯著；效果量弱，稱「剖面關聯」而非「梯度驅動」。
  • 上面每個 gap 的 bootstrap 95% CI 都寬達 43pp 以上，其中兩條含 0 （has_tests_or_evals 與 readme_has_before_after 皆 [−11.9, 85.7]）。 T3 層只有 n = 3，這是結構性必然。含 0 的意思是「就星階梯度這條證據而言，與沒有梯度無法區分」—— 權重仍保留，是因為它們另有草根復現、機制陳述、證據強度三條獨立證據線。 CI 不是顯著性檢定。
  • craft 判定的審查者間一致性尚未量測。本頁的核心主張是 「craft 非靠 LLM 判讀不可」，但兩個獨立審查者會不會給同樣結論，目前沒有數據。 協定與樣本已預先登記，尚未執行。
  • hygiene 門檻多數來自官方規範三角驗證（樣本以合規 SKILL.md 篩選，多數 hygiene 特徵天花板化）。
  • 已知偏斜：T0 領域偏 design-ui；C3 世代 n=3 過薄（複算封頂 weak）。
